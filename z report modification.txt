# Dashboard Access Block Feature

Allow the school **super admin** to block HR admins and supervisors from accessing the school's admin dashboard without suspending them system-wide. The blocked user can still use the mobile app for normal clocking. The super admin can reverse the block at any time.

The control panel for this feature lives on the existing **Roles & Permissions** page and is **only visible to super admins**.

---

## Proposed Changes

### Backend

#### [MODIFY] [user.entity.ts](file:///d:/source_codes/school_clocking_system/backend/src/modules/users/user.entity.ts)
Add three new nullable/defaulted columns:
- `isDashboardBlocked: boolean` (default: `false`)
- `dashboardBlockReason: string | null`
- `dashboardBlockedAt: Date | null`

#### [MODIFY] [employees.service.ts](file:///d:/source_codes/school_clocking_system/backend/src/modules/employees/employees.service.ts)
- Add `ALTER TABLE` migrations in `onModuleInit` for the three new `users` columns (matches existing pattern).
- Add `setDashboardBlock(employeeId, blocked, reason, adminUser)` method that:
  - Looks up the employee, validates it belongs to the same tenant.
  - Ensures only `hr_admin` or `supervisor` users can be blocked (super admins are immune).
  - Updates `user.isDashboardBlocked`, `user.dashboardBlockReason`, `user.dashboardBlockedAt`.
  - Writes an audit log entry.

#### [MODIFY] [employees.controller.ts](file:///d:/source_codes/school_clocking_system/backend/src/modules/employees/employees.controller.ts)
Add `PATCH /employees/:id/dashboard-access` — requires `JwtAuthGuard` + `super_admin` role only. Body: `{ blocked: boolean, reason?: string }`.

#### [MODIFY] [auth.service.ts](file:///d:/source_codes/school_clocking_system/backend/src/modules/auth/auth.service.ts)
In `validateUser`, after the existing `inactive`/`suspended` checks, add:
```ts
if (isWebDashboardLogin && user.isDashboardBlocked) {
  throw new UnauthorizedException(
    'DASHBOARD_ACCESS_BLOCKED: Your access to the admin dashboard has been restricted by the school administrator.'
    + (user.dashboardBlockReason ? ` Reason: ${user.dashboardBlockReason}` : '')
  );
}
```
Mobile app logins skip this check because `context` is not `'central_dashboard'`.

### Frontend

#### [MODIFY] [store.ts](file:///d:/source_codes/school_clocking_system/dashboard/src/lib/store.ts)
Add `isDashboardBlocked?: boolean` to the `AuthUser` interface.

#### [MODIFY] [api.ts](file:///d:/source_codes/school_clocking_system/dashboard/src/lib/api.ts)
Add to `employeesApi`:
```ts
setDashboardAccess: (id: string, blocked: boolean, reason?: string) =>
  api.patch(`/employees/${id}/dashboard-access`, { blocked, reason }),
```

Also add a new `permissionsApi` section:
```ts
listAdminStaff: () => api.get('/employees', { params: { roles: 'hr_admin,supervisor', limit: 200 } }),
```

#### [NEW] [dashboard-blocked/page.tsx](file:///d:/source_codes/school_clocking_system/dashboard/src/app/dashboard-blocked/page.tsx)
A premium standalone page shown when a blocked user tries to access the dashboard. Features:
- Large animated lock icon
- "Dashboard Access Restricted" heading
- Personalized message + block reason (if any)
- "Contact your administrator" info
- Logout button

#### [MODIFY] [layout.tsx](file:///d:/source_codes/school_clocking_system/dashboard/src/app/(protected)/layout.tsx)
In the `useEffect` that calls `authApi.me()`, if the returned user has `isDashboardBlocked === true`, immediately redirect to `/dashboard-blocked` instead of letting them in.

#### [MODIFY] [permissions/page.tsx](file:///d:/source_codes/school_clocking_system/dashboard/src/app/(protected)/permissions/page.tsx)
Add a new section **below** the existing permissions matrix, visible **only when `user.role === 'super_admin'`**:

- **Section header**: "Dashboard Access Control" with a shield/lock icon and a description.
- **"Manage Restrictions" button** in the section header → opens the management modal.
- **Management Modal**:
  - Title: "Dashboard Access Restrictions"
  - Search bar to filter staff by name.
  - Scrollable list of all HR Admins & Supervisors in the school, each showing:
    - Avatar initials + full name + role badge
    - Status badge: `RESTRICTED` (red) or `FULL ACCESS` (green)
    - If restricted: shows reason + date blocked
    - Action button: **"Block Access"** or **"Restore Access"** 
  - Clicking "Block Access" opens a small inner panel to enter an optional reason, then confirm.
  - Clicking "Restore Access" unblocks immediately with a confirmation toast.

## Verification Plan

### Manual Verification
1. Log in as super admin → go to Permissions page → see the new "Dashboard Access Control" section.
2. Block an HR admin with a reason → confirm modal closes and list shows `RESTRICTED` badge.
3. Log out → try to log in as the blocked HR admin → expect to see the `/dashboard-blocked` page with the correct reason.
4. Log back in as super admin → restore access → confirm badge changes to `FULL ACCESS`.
5. Log in as the HR admin again → confirm normal dashboard access is restored.
6. Confirm the blocked HR admin can still use the mobile app (mobile context does not send `central_dashboard`).
